## Що нового

- **Надішліть матч розробникові.** Коли ввімкнено «Зберігати записи матчів тиждень» («Налаштування → Ще налаштування»), біля кожного запису є кнопка «Надіслати розробникові». Вона відкриває підтвердження: що піде (що гра повідомила про вашого героя за матч і всі показані поради) і що ні (нік, Steam ID, ID облікового запису, номер матчу, ключ доступу гри, чат, дата й час матчу). Кожен запис потребує окремої згоди, самі записи нікуди не йдуть. Після надсилання запис має номер `S-XXXXXX`, і кнопка змінюється на «Надіслано».
- **Копія ще безособовіша за файл.** Копія для надсилання повторно проходить очищення, не має номера матчу й назви локального файлу, а всі часи в ній ідуть від початку запису. Якщо в копії щось приватне лишилося, застосунок її не надсилає. Копія до 20 МБ.
- **Сервер.** Запис лежить у Cloudflare R2 **60 днів**, потім видаляється сам. Сервер лише перевіряє початок файлу. Ліміти: 3 записи на годину з одного встановлення, 10 з однієї адреси, до 1,5 ГБ на добу й 8 ГБ разом. Ідентифікатор встановлення з записом не зберігається (лише хеш із сіллю для ліміту), потрібен ключ пристрою. Матч, який ще записується, надіслати не можна. Його читає лише розробник, щоб налаштовувати поради. Видалити раніше можна кнопкою «Видалити мої дані на сервері».
- **Вибірка.** Сервер може пропонувати кнопку лише частині встановлень: частку і саму можливість він регулює без нового випуску (`/v1/config`).
- **Розробнику.** `scripts/fetch_recordings.py` завантажує записи в `backend/session_records/cloud/`, розділені на `tune` (на них налаштовують правила) і `holdout` (на них лише перевіряють; ≈ 25 %, сторона залежить від номера запису). Сторінка «Конфіденційність» описує надсилання.

**In English:**

- **Send a match to the developer.** With «Keep match recordings for a week» on (Settings → More settings), each recording has a «Send to developer» button. It opens a confirmation: what goes (what the game reported about your hero during the match and every advice shown) and what does not (nickname, Steam ID, account ID, match ID, the game's access token, chat, the date and time of the match). Every recording needs its own consent; nothing is sent by itself. After sending, the recording has a number `S-XXXXXX` and the button becomes «Sent».
- **A copy more anonymous than the file.** The copy goes through the redaction again, has no match ID or local file name, and all its times count from the start of the recording. If anything private is left in it, the app does not send it. A copy is at most 20 MB.
- **The server.** The recording sits in Cloudflare R2 for **60 days** and is then deleted by itself. The server only checks the beginning of the file. Limits: 3 recordings an hour per installation, 10 per address, up to 1.5 GB a day and 8 GB in total. The installation id is not stored with a recording (only a salted hash, for the limit), and a device key is required. A match that is still being recorded cannot be sent. Only the developer reads it, to tune the advice. «Delete my data on the server» removes it earlier.
- **Sample.** The server can offer the button to only part of the installations: the share and the feature itself are controlled by the server without a new release (`/v1/config`).
- **For the developer.** `scripts/fetch_recordings.py` downloads recordings into `backend/session_records/cloud/`, split into `tune` (rules are set on them) and `holdout` (they only check; about 25 %, the side follows the recording's number). The Privacy page describes the sending.
