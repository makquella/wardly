## What it does

| During the match | After the match |
|---|---|
| ![Urgent advice: leave the wave and reset HP](site/assets/overlay/en/lowhp.webp) | ![AI coach review](site/assets/app/en/review-ai.jpg) |
| A card over the game (and out loud) at the right moment: low HP, farm pace for your position against this opponent, counter items for the enemy draft, your hero's own saves, skill order, map timers. | A score per area, the three things to fix next game, where you died and why, item timings against your rank, a match map, and an optional AI review where every number is checked against the match data. |

- **Every role.** Full advisor for 64 heroes (carries, mids, offlaners, supports); survival advice for every other hero.
- **Progress over weeks.** Trends, recurring problems, a focus goal tracked match by match, MMR history.
- **Your data stays yours.** History, notes and keys live on your computer. Anything sent anywhere is opt-in and listed on the [privacy page](https://luhovyimvp.dev/privacy.html).
- **Ukrainian and English** in the app, the overlay, the voice and the site.

## How it works

Wardly reads only Valve's official Game State Integration (GSI): Dota posts the visible game state to a local HTTP endpoint. No memory reading, no screen capture, no input automation, no injection.

```mermaid
flowchart LR
    Dota[Dota 2 GSI] -->|HTTP, localhost| API[FastAPI backend]
    Replay[Replay demo] --> API
    API --> Norm[State normalizer]
    Norm --> DP[Decision points]
    DP --> Rec[Rule-based recommender]
    Rec --> Sched[Advice scheduler]
    Sched --> Overlay[Electron overlay + voice]
    API --> Store[(SQLite history)]
    Store --> Review[Post-match analysis]
    Review -. optional .-> LLM[AI review, fact-checked]
    App[Electron launcher] -->|starts, supervises| API
    App -. opt-in .-> Worker[Cloudflare Worker + D1]
```

- **Rules decide, AI only explains.** Live advice comes from deterministic, tested rules: what to say, when, how urgent, and how often. The optional AI writes the post-match review on top of deterministic facts, and its numbers are verified against them.
- **Unknown stays unknown.** GSI shows what you can see. The coach never guesses hidden enemies or team readiness, and it stays quiet when a signal is missing.
- **One local process tree.** The desktop app owns one backend on a free local port, with separate tokens for control and GSI, Origin and Host checks, and bounded request bodies.

More: [Architecture](docs/ARCHITECTURE.md) · [Advice scheduler](docs/ADVICE_SCHEDULER.md) · [Local API security](docs/LOCAL_API_SECURITY.md) · [Desktop security](docs/DESKTOP_SECURITY.md)

## Install on Linux

Download from the [latest release](https://github.com/makquella/wardly/releases/latest):

- **Arch / CachyOS / Manjaro:** `sudo pacman -U Wardly-<version>-x86_64.pacman`
- **Debian / Ubuntu / Mint:** `sudo apt install ./Wardly_<version>_amd64.deb`
- **Any distro:** `chmod +x Wardly-<version>-x86_64.AppImage && ./Wardly-<version>-x86_64.AppImage` (needs `fuse2`/`libfuse2`; self-updates)

Run Dota 2 in «borderless window» mode so the overlay can sit on top. Details, optional tools and limits: [`docs/PACKAGING_LINUX.md`](docs/PACKAGING_LINUX.md).

## Getting started (development)

Requirements: Python 3.11, Node 22. Windows is the main platform and Linux (x86_64; Arch/CachyOS first) is supported too; the backend, the desktop app in dev mode and all tests also run on Linux.

```bash
# backend
cd backend
python -m venv .venv && source .venv/bin/activate
python -m pip install --require-hashes --only-binary=:all: -r requirements-dev.txt

# desktop app: starts its own backend on a free port, the overlay and the tray
cd ../frontend/launcher
npm ci
npm run dev
```

No Dota at hand? The launcher's demo mode replays a recorded match through the real backend and overlay: [Replay demo](docs/REPLAY_DEMO.md).

### Checks

```bash
python scripts/dev.py check --changed --dry-run   # shows what would run for your changes
python scripts/dev.py check --changed             # runs it
python scripts/dev.py check --full                # backend, desktop, Worker, site and version gates
```

CI runs the same gates on every pull request, plus a Windows build that installs the NSIS package and smoke-tests it. Details: [Testing](docs/TESTING.md) · [Dev runner](docs/DEV_RUNNER.md) · [Type checking](docs/TYPE_CHECKING.md).

### Code signing policy

The Windows installer is not code-signed yet, so SmartScreen may warn on first run («More info» → «Run anyway»). SignPath Foundation's program for open source has not accepted Wardly yet; we will apply again with a larger audience.

- **Verify a download.** GitHub Actions ([`release.yml`](.github/workflows/release.yml)) builds the installer from this repository at the release commit. The website shows its SHA-256 next to the download button; compare it with `Get-FileHash`. Release notes link a VirusTotal report when one was made.
- **Once signed.** Only the Wardly installer and the app inside it, built from this repository; every signing request approved manually.
- **People.** Committer, reviewer and release approver: [makquella](https://github.com/makquella). Pull requests from anyone else are reviewed before merge.
- **Privacy.** [luhovyimvp.dev/privacy.html](https://luhovyimvp.dev/privacy.html): what the app sends, where, and how to turn it off.

The same policy on the website: [luhovyimvp.dev/code-signing.html](https://luhovyimvp.dev/code-signing.html).
